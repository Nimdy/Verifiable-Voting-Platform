# ADR-0009: A signed digital↔paper anchor binds the bulletin-board root to the paper ballot manifest; secret-ballot paths are audited by ballot-polling RLAs, never per-ballot CVRs

**Status:** Accepted

## Context
[ADR-0004](ADR-0004-paper-ballots-of-record-plus-risk-limiting-audits-are-the-on.md) designates voter-verified paper ballots of record plus a mandatory risk-limiting audit (RLA) as the only software-independence anchor, confined to the supervised polling-place profile, and names `rla/` tooling. That ADR sets the policy; this ADR fixes the concrete artifacts and a privacy-load-bearing implementation rule. Two failure modes must be prevented by construction: (1) someone swaps the paper batches OR the published digital transcript after the fact, so the RLA audits a different universe than the public verified; (2) the audit export leaks how individuals voted. A risk-limiting audit also comes in two families: ballot-*comparison* (needs a per-ballot cast-vote record — CVR — to compare against a hand read of each sampled paper ballot) and ballot-*polling* (samples paper, hand-reads, runs a sequential hypothesis test on the reported winner; needs NO CVRs). The engine's secret-ballot paths (plurality / multi-seat / Borda) decrypt only per-candidate totals and never an individual ballot — that is the ballot-secrecy guarantee — so a per-ballot CVR is not merely unavailable, it would be a privacy violation to manufacture.

## Decision
Ship an export + anchor layer (`reference/src/rla.ts`) that (a) computes a `paperManifestRoot` (RFC-6962 root over canonical, sorted paper-batch rows, using the same CVE-2012-2459-safe `BulletinBoard` Merkle implementation as the digital board); (b) binds it to the published digital `boardRoot`, the ballot counts, and the election public key inside ONE `PaperAnchor` signed by a named election-authority key (Schnorr/ristretto255, domain-separated `vvp-anchor-v1` frame) and publicly re-verifiable by `verifyAnchor` (which never throws); (c) emits a ballot manifest in the exact columns VotingWorks Arlo and SHANGRLA ingest, plus a ballot-polling reported-results export. **Hard rules:** secret-ballot tallies are exported for ballot-POLLING RLAs ONLY and a per-ballot CVR is NEVER emitted for them; only the mixnet-IRV path, whose anonymized ranking multiset is already public, may export anonymized CVRs. A paper/digital count mismatch is a flagged discrepancy resolved by the canvass/RLA — **paper wins** (ADR-0004) — not a halt. The engine does NOT re-implement authoritative RLA statistics; the included top-two BRAVO calculation is explicitly illustrative/non-authoritative, and the audit of record is Arlo/SHANGRLA run on the paper. The on-chain adapter, if used, anchors only the signed roots (~64 bytes), never a ballot (ADR-0002).

## Consequences
GOOD: the published digital record and the physical ballots are cryptographically cross-bound, so a post-hoc swap of either is detectable by anyone; the profile produces real inputs for production RLA tooling rather than a bespoke pseudo-audit; ballot secrecy is preserved by construction because no secret-ballot CVR is ever produced; the honest line from ADR-0004 (paper = software independence, digital = transparency) is enforced in the artifacts and copy. BAD/COSTS: the operational burden of ADR-0004 remains (printing, custody, manifests, audit staffing); the anchor binds records but cannot attest that the paper batches *physically* match reality — chain-of-custody, scanner interpretation, and the RLA ceremony are off-system and must be disclaimed; the illustrative BRAVO function must be conspicuously labelled non-authoritative so no one mistakes it for the audit. These are accepted: an export+anchor that feeds the real audit tools is honest and useful, whereas re-implementing RLA statistics would invite over-reliance on un-reviewed code.

## Alternatives considered
(1) Ballot-comparison RLA with per-ballot CVRs for all paths — REJECTED for secret-ballot tallies: it requires per-ballot interpretations, which breaks ballot secrecy; polling audits achieve software independence without CVRs. (2) Re-implement authoritative RLA statistics (ALPHA/ONEAudit, stratification) in-engine — REJECTED: high-stakes statistical code that production tools (Arlo/SHANGRLA) already provide and that deserves its own audit; we export inputs instead. (3) Anchor only the digital board root (no paper binding) — REJECTED: leaves the paper↔digital swap undetected, defeating the point. (4) Halt verification on a paper/digital count mismatch — REJECTED: contradicts paper-wins; a discrepancy is exactly what the canvass/RLA exists to resolve, so it is surfaced, not fatal.
