# ADR-0012: The Terelius–Wikström O(N) proof of shuffle ships EXPERIMENTAL and opt-in; Sako–Kilian cut-and-choose stays the default mix path

**Status:** Accepted (experimental module shipped; promotion to default gated on an external audit)

## Context
The verifiable re-encryption mixnet (`mixnet.ts`) uses a **Sako–Kilian cut-and-choose** proof: its soundness is a one-paragraph transitivity argument and every verifier step is a group-element equality or a finite bijection test — *by-hand checkable*, which is this project's non-negotiable. Its cost is an O(t·N) proof (t = 128). The documented efficiency upgrade is an **O(N) proof of shuffle** (Terelius–Wikström 2010 / Wikström 2009, or Bayer–Groth 2012) — the construction Verificatum uses in production.

A proof of shuffle is, however, **the most soundness-treacherous primitive in the field.** The 2019 SwissPost/Scytl break (Haines–Lewis–Pereira–Teague; Lewis–Pereira–Teague) was a **missing check** in exactly this kind of proof — it **passed expert audit** — that let a malicious mixer alter votes while the proof still verified. A design panel + soundness skeptic (recorded in CRYPTO_REVIEW round 19) ruled that a *sound, by-hand-checkable* O(N) shuffle is **not** shippable to "default" standard here-and-now: the verifier-facing equations are nameable, but the soundness lives in the product-argument *interior* (the committed-multiplication steps), which is exactly the region that historical breaks hid in. Verifier-equation enumeration that hand-waves the interior reproduces the failure mode it warns against.

## Decision
Ship `reference/src/mixnet-tw.ts` as an **EXPERIMENTAL, opt-in** O(N) Terelius–Wikström re-encryption shuffle, **alongside** (not replacing) `mixnet.ts`. **Sako–Kilian remains the default mix/IRV path.** The module is built to the project's incremental discipline (sound primitive + independent verifier + adversarial tests *before* it is wired into any election), with the soundness-critical interior implemented as constructs the verifier can trace:

- **NUMS generator vector** `h_i = ristretto255_from_hash(SHA-512("vvp-tw-gen-v1|" + i))` — the same RFC-9496 one-way map that derives the audited `H`, byte-identical in `@noble` and libsodium (verified: pinned `h_0 = 805862…`, fold `260f4c4a…`; all distinct, none = G/H/identity). The verifier **re-derives** the vector and never reads generators from a proof.
- **Permutation commitment** `c_i = h_{π(i)} + r_i·H`, committed **before** the Fiat–Shamir challenge vector `e` (this is the soundness crux — it removes the adaptive-permutation choice that would otherwise let a prover pick a lucky permutation after seeing `e`, since `n! ≫ N`).
- A **combined generalized-Schnorr** (one challenge) proving, sharing the *same* committed weights `g`: the commitment-consistency `D = Σ gⱼ·hⱼ + r_D·H` (binds `g` to the pre-committed `c`); each `Γⱼ = gⱼ·G + γⱼ·H`; and, for **every** component `w`, the re-encryption multi-exponentiation on **both** the `a` and `b` sides.
- A **product argument** `∏(gⱼ−x) = ∏(eᵢ−x)` (⇒ `{g}={e}` ⇒ a genuine permutation, not merely row-sums), realized as a partial-product chain whose every step is a **committed-multiplication generalized Schnorr** (structurally the existing `proveConsistency`), with both endpoints checked and the target `∏(eᵢ−x)` **verifier-computed**.

It is held to the two-verifier bar (a byte-identical Python `verify_tw_shuffle`, cross-checked with **zero divergence** across a tamper battery including the four known attack classes) and a self-test suite (`selftest.ts` §26).

### EXACT honest-scope wording (strongest TRUE claim)
> `mixnet-tw.ts` is a **pre-audit, EXPERIMENTAL, opt-in** O(N) Terelius–Wikström re-encryption-shuffle NIZK. Given the re-derived CRS, `pk`, an `L0` the consumer re-derives from validated ballots, and output `L`, it establishes that `L` is a re-encryption under `pk` of a **genuine permutation** of `L0` — every item moved as a whole (all `W` components by the same permutation), none dropped, duplicated, or altered, with the vote-bearing component preserved up to re-encryption — with **single-instance** soundness ≈ (2n+c)/N_order ≈ 2⁻¹²⁸…2⁻²⁵⁰ under Fiat–Shamir/ROM + dlog on ristretto255. Two independent implementations (TS + Python/libsodium) accept the honest proof and reject every tamper in the battery, with zero divergence.

### MUST-NOT-CLAIM
- ❌ **NOT externally audited.** A hand-rolled shuffle proof — even cross-verified by a second independent implementation and adversarially reviewed in-house — is **not** externally audited. **The 2019 SwissPost/Scytl break passed expert audit.** Cross-verification + an adversarial battery *reduce* but do **not eliminate** the risk of a subtle missing-check soundness gap in the interior. **For production use an externally-audited mixnet (Verificatum), not this module.**
- ❌ NOT the default and NOT a drop-in replacement. Sako–Kilian (`mixnet.ts`) stays default until (a) the interior is cross-checked against Verificatum's documented equations **and** (b) an external audit, **and** (c) the adversarial suite (incl. the four attack classes) stays green.
- ❌ NOT "2⁻¹²⁸ from t repetitions." TW is **single-instance** — no `SECURITY_T` floor; soundness rests on field size + a complete Fiat–Shamir transcript.
- ❌ NOT "as by-hand-checkable as the cut-and-choose." The final equations are short, but the product-argument interior is multi-step — do not claim parity with Sako–Kilian's one-paragraph transitivity argument.
- ❌ Does NOT prove ballot validity (that is `ranked.ts` pre-shuffle, unchanged), and does NOT hide `n`, `W`, or the plaintext multiset (revealed by the later threshold decryption — the point of a mixnet). No coercion-resistance / receipt-freeness. Privacy of `π` is computational (DDH + FS/ROM), not unconditional.
- ❌ Not constant-time — out of scope for a reference engine; stated, not hidden.

## Consequences
GOOD: the kernel now has a working, cross-verified, adversarially-tested reference implementation of the O(N) construction that closes the one axis where it was measurably behind Verificatum — a real starting point for a future audited version, and a concrete artifact to compare against. The honest scope is enforced in the module header, the demo, this ADR, and the verifiers. BAD/COSTS: it is experimental and behind the default; a residual subtle-soundness risk in the hand-rolled interior cannot be excluded without external audit (hence the labeling and the gate); the interior is less by-hand-obvious than the cut-and-choose. These are accepted: an honestly-scoped, cross-verified experimental module that says exactly what it is — and is **not** wired into any election — is a useful increment, whereas promoting it to default without an external audit would be exactly the over-claim, and exactly the failure mode (SwissPost), this project exists to avoid.

## Alternatives considered
(1) **Promote TW to the default mix path now** — REJECTED: the interior is where soundness breaks hide and it has not been externally audited; promotion is gated. (2) **Bayer–Groth instead of Terelius–Wikström** — REJECTED for this kernel: asymptotically smaller but its recursive product/Hadamard arguments are human-untraceable, a larger audit surface, exactly the SwissPost danger zone; TW's short final equation list is more by-hand-checkable. (3) **Do not implement O(N) at all** — viable (Sako–Kilian works and is the default), but the cross-verified experimental module is a valuable, honestly-scoped upgrade-path artifact. (4) **Integer/trusted generators** — REJECTED: the CRS is NUMS and re-derived by the verifier; a generator vector with a known discrete-log relation is precisely how a permutation commitment opens to a non-permutation.
