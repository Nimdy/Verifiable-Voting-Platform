# ADR-0002: The blockchain is non-load-bearing: anchor only signed Merkle roots, never ballots

**Status:** Accepted

## Context
The project name and 2014 origin imply a blockchain at the trust root: the original concept recorded every AAVET vote as an on-chain transaction (Steps 7-17). The published expert consensus (NASEM 2018 'Securing the Vote'; Park, Specter, Narula & Rivest 2021 'Going from Bad to Worse'; Specter, Koppel & Weitzner 2020 on Voatz) is that a blockchain does little for the properties that actually matter (cast-as-intended, ballot secrecy, eligibility, coercion-resistance), introduces fresh vulnerabilities, and that an immutable ledger LOCKS IN fraud committed at the endpoint. The legitimately useful job a chain can do is narrow: tamper-evident, third-party-witnessable timestamping of a commitment. The reference bulletin board (src/bulletin.ts) already provides authenticated append-only storage with an RFC-6962-style Merkle root that commits to the full ordered ballot set; the independent verifier (src/verify.ts) recomputes that root from the published ballots. None of that requires a chain.

## Decision
The trust root is peer-reviewed cryptography (ElGamal + Chaum-Pedersen NIZKs + threshold decryption + the Merkle bulletin board), NOT any chain. The BulletinBoard port is the single chain-pluggable seam, with the DEFAULT adapter being a Postgres transparency log (Trillian/Sigstore-style signed tree heads, RFC 6962 semantics) and NO chain. Optional anchor-* adapters (anchor-evm via viem, anchor-cosmos on permissioned CometBFT, anchor-bitcoin via OP_RETURN) write ONLY the ~32-byte signed Merkle root / signed tree head to the chain. Encrypted ballots, validity proofs, decryption shares, and any voter-linked data NEVER go on-chain. An anchor is purely a redundant witness to the root for timestamping and tamper-evidence; removing every anchor MUST NOT change which elections verify. A conformance test suite runs identical inclusion-proof vectors against every BulletinBoard adapter so 'the chain is swappable and optional' is tested, not asserted; multiple anchors may run in parallel ('belt and suspenders') by configuration only.

## Consequences
GOOD: the system is fully verifiable with zero chain dependency (no gas, no L1 liveness/finality coupling, no MEV/reorg concerns on the critical path); ballots stay private and small, avoiding the 'fraud locked in forever' failure mode for the data that matters; anchoring becomes an a-la-carte transparency enhancement rather than a liability; aligns directly with Park et al.'s finding that a plain authenticated log does the bulletin-board job more simply and reliably; chain choice (EVM/Cosmos/Bitcoin/none) is a deployment decision, not an architecture rewrite. BAD/COSTS: a chain no longer provides decentralized replication of the ballot set itself, so availability/replication of the full transcript must be solved separately (object-store mirrors, multiple log witnesses, gossiped signed tree heads); operators tempted by 'on-chain = trustworthy' marketing may be disappointed that the chain is deliberately minimized; an anchor only proves a root existed at a time -- it cannot prove the root committed to honest ballots (that is the verifier's job), which must be communicated clearly so anchoring is not over-trusted.

## Alternatives considered
(1) Full ballots on-chain (the original concept) -- rejected: privacy-destroying or requires putting ciphertext+proofs on L1 at high cost, and immutability locks in endpoint fraud (NASEM/Park et al.). (2) Chain as the canonical bulletin board with ballots in calldata/blobs -- rejected: couples liveness and verification to a specific chain, reintroduces reorg/finality ambiguity vs. 'immutable', and is more complex than a signed log for no security gain. (3) No external anchoring at all, log-only -- viable and is effectively the default; anchoring is kept as an OPTION because a public-chain timestamp is a cheap, independent witness that strengthens tamper-evidence against a log operator who tries to fork history, so it is offered rather than mandated.
